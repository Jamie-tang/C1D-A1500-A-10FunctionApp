# ASC 故障码解析工具

WPF 上位机工程，用于解析 Vector ASC 日志中的固件定时主动上传及 `Can_DebugDataAckSub()` 返回的 PDF 故障报码。

## 使用方法

1. 使用 Visual Studio 2022 打开 `FaultCodeAscParser.sln`，或在工程目录执行 `dotnet run`。
2. 点击“打开 ASC 文件”，选择 `.asc` 日志；大文件读取期间会显示字节读取进度，并暂时禁用打开、帧 ID 筛选和报文选择，读取完成后自动恢复。
3. 上方列表显示所有成功解析出的 CAN 数据帧，不过滤 CAN ID、方向或 `data0`。
4. 在“帧 ID 筛选”中输入 ID 的任意十六进制片段（例如 `1810`、`1080`），可筛选符合的报文；留空显示全部报文。
5. 选中任意一条报文：
   - 只有扩展帧 ID、`data0 = 0x10`~`0x14` 页面和数据长度同时符合故障报码协议时，才进入故障解析；
   - CAN ID 最低字节 `xx` 必须是电源地址 `0x80`~`0x8B`；
   - 只有实时位图、锁存位图或首故障码中存在故障时，下方才显示对应 PDF 故障名称；
   - 不符合故障报码协议或不存在置位故障的报文不显示无关解析内容。

## 固件协议对应关系

| CAN ID | data0 | 故障内容 |
|---|---:|---|
| `0x1F1C10xx` | `0x10` | 充电器实时/锁存故障及首故障码 |
| `0x1F1D10xx` | `0x11` | 电池实时故障、电池状态原始值、输出建立超时标志 |
| `0x1F1E10xx` | `0x12` | 电池锁存故障和 MOS 状态原始值 |
| `0x1F1F10xx` | `0x13` | RS485 握手阶段故障 |
| `0x1F2010xx` | `0x14` | RS485 周期查询故障 |

其中 `xx` 为 `0x80`~`0x8B`。上位机同时保留 `Can_DebugDataAckSub()` 使用 `0x1F1C10xx` 回复 `data0 = 0x10`~`0x14` 页面的解析。

位图规则：PDF 编号 1 对应 bit0，PDF 编号 32 对应 bit31。首故障码为 `0xDDNN`，高字节 `DD` 是故障域，低字节 `NN` 是该域 PDF 故障编号。

> 注意：该工程要求 ASC 第一行必须是可识别的 `date` 时间基准。所有 CAN 报文显示时间均为该基准加上报文第一列的相对秒时间戳，并固定以 24 小时制显示。若文件首行不符合该格式，工具会提示解析失败，不会回退为相对时间。
